01 开始 / OVERVIEW LZR / DOCS

插件能做什么

插件就是一个 ZIP。解压后真正起作用的文件有两类：清单说明它需要什么，Lua 说明它做什么。 客户端不执行包里的 JavaScript，也不会把 Flutter Widget 交给 Lua， 能做的事都得经过 host 提供的接口。

01 / PROVIDER

接入一个音乐平台

搜索、专辑、歌单、播放地址、歌词、播放上报、一起听。实现 describe 和用得到的操作，平台就会出现在「添加平台」里，界面跟内置平台一样。

02 / HOST

调用宿主能力

host.http 按清单里的白名单发请求，host.crypto 负责签名， host.storage_* 存会话。也可以开 TCP 或 WebSocket 连接， 甚至在本机监听端口，给外部前端用。

03 / UI

扩展界面

可以加设置项、插件页面、正在播放页的菜单项，也能提供主题和布局规则。 控件都由宿主绘制，插件只交数据。

边界

插件拿不到 Dart 对象、Flutter Widget、宿主的文件路径、进程和动态库， 也读不到别的插件的数据。这一点没法用配置放开： Lua 里能看见的只有 host 和你自己返回的 table。

02 开始 / PACKAGE ZIP LAYOUT

插件包结构

插件以 ZIP 形式安装。manifest.json 必须放在 ZIP 根目录， entry 指向的 Lua 文件也要在包里。其余 Lua 文件用 require 加载。 

my-plugin.zip
├── manifest.json      # 必需，唯一的清单来源
├── main.lua           # 必需，entry 指向它
├── api.lua            # 可选，require("api") 加载
├── sign.lua           # 可选，require("sign")
├── data/keys.json     # 可选，host.resource("data/keys.json") 读取
├── frontend/          # 可选，随包携带的只读 HTML/CSS/JS
│   └── index.html
├── README.md          # 可选
└── LICENSE            # 可选

体积与文件限制

限制数值说明
ZIP 大小16 MB超过直接拒绝安装
解压后总量8 MB所有文件累计
单文件2 MB任意一个文件
文件个数256压缩包内有效条目
路径长度200相对路径字符数

允许的文件类型只有：manifest.json、*.lua、 .json / .md / .txt / .html / .css / .js / .svg 文本资源，以及根目录的 LICENSE。出现别的扩展名时整包拒绝，不会只装能认出来的那部分。

路径规则

所有路径必须是安全的相对路径：不含反斜杠、盘符或开头的 /， 不允许 . 与 .. 段，不允许以点或空格结尾的段， 也不允许 < > " | ? * 与控制字符。路径按小写去重，所以 Api.lua 和 api.lua 属于冲突。

打包工具留下的杂物直接忽略，不算错误：__MACOSX/、.DS_Store、Thumbs.db。 Windows 资源管理器写出的反斜杠路径会被规范化。打包时多裹了一层目录、 所有文件都在同一个顶层目录下的，客户端会把这一层提升为根。

提示

自动提升只对「所有文件共用一个顶层目录」有效。ZIP 里既有 my-plugin/manifest.json 又有根目录的 README.md 时不会提升，安装会报「ZIP 根目录缺少 manifest.json」。

03 开始 / MANIFEST SCHEMA 1

清单字段

manifest.json 是插件唯一的声明来源，决定插件叫什么、入口在哪、能访问哪些网络、 在客户端里显示成什么样。字段不合法时整包被拒，而报错不会告诉你是哪个字段， 所以下面这些规则需要逐条对。

id string
插件唯一标识，^[a-z][a-z0-9_.-]{2,79}$：小写字母开头，3–80 位。 建议用反写域名，例如 community.bilibili.music。
name string
显示名称，非空且不超过 100 字符。
version string
语义化版本，例如 1.4.2 或 2.0.0-beta.1。与市场清单里的 version 必须完全一致。
apiVersion number
当前只接受 1。写成别的值（包括遗漏时的默认 0）一律拒绝。
provider string
^[a-z][a-z0-9_-]{1,39}$：小写字母开头，2–40 位，且不能是保留字 local。 运行时每次 call 都会把它放进 args.platform。
entry string
入口 Lua 文件，默认 main.lua。必须是安全相对路径且以 .lua 结尾。
description string
一句话说明，显示在插件详情里。
author string
作者或团队名。
capabilities string[]
声明这个插件实现了哪些能力。客户端据此决定首页模块、菜单入口和要不要广播播放事件。 名字不区分大小写与 - / _。
auth string[]
登录方式：qr、sms、password、cookie。写了才会显示对应入口。
permissions object
权限声明，详见 权限清单。未声明的权限不会弹窗，也不会生效。

完整示例

{
  "id": "community.example.music",
  "name": "Example Music",
  "version": "1.0.0",
  "description": "把 Example Music 接进 Lazer",
  "author": "YOUR NAME",
  "entry": "main.lua",
  "apiVersion": 1,
  "provider": "example",
  "capabilities": ["search", "playlists", "lyrics", "scrobble", "player_events"],
  "auth": ["qr", "cookie"],
  "permissions": {
    "network": ["api.example.com", "*.example-cdn.com"],
    "storage": true,
    "data": ["library", "profile"]
  }
}

网络规则语法

permissions.network 是 HTTPS 主机的白名单，最多 32 条。每条是一个主机名， 可带端口，也可以用 *. 前缀通配子域。

写法允许不允许
api.example.com恰好这个主机任何子域、任何其他主机
*.example.comexample.com 及其所有子域example.org
api.example.com:8443同主机且端口为 8443443 或其他端口
*.com拒绝安装：通配必须落在可注册域名上

通配符后面必须是一个可注册域名。客户端内置了一小张公共后缀表（co.uk、 com.cn、co.jp 等），把 *.co.uk 这类写法判为无效； 想覆盖国别域名下的子域，请写完整的 *.example.co.uk。 请求必须使用 HTTPS，且 URL 中不能带用户名或密码。

说明

*.example.com 额外允许裸域 example.com 本身。 端口不写时要求目标端口为默认 443；写了端口就要求精确相等。

04 开始 / QUICKSTART HELLO, PROVIDER

第一个插件

最小的插件只需要一个入口文件和一个 call 函数。 下面这份能登录、能搜索、能取歌词，够出现在平台列表里了。 

-- main.lua
local api = require("api")

return {
  call = function(operation, args)
    if operation == "describe" then
      return { providers = {
        { id = "example", name = "Example Music",
          auth = { "cookie" },
          capabilities = { "search", "lyrics" } },
      } }
    end

    if operation == "session" then
      local cookie = host.storage_get("cookie")
      if not cookie then return nil end
      return { id = "me", name = "Example User" }
    end

    if operation == "loginCookie" then
      host.storage_set("cookie", args.cookie)
      return { id = "me", name = "Example User" }
    end

    if operation == "search" then
      return api.search(args.query, args.limit or 30, args.offset or 0)
    end

    if operation == "lyrics" then
      return api.lyrics(args.id)
    end

    error("unsupported operation: " .. tostring(operation))
  end,
}
-- api.lua
local M = {}

local BASE = "https://api.example.com"

-- 参数既可以直接给查询串，也可以给 table；table 会被编码成 a=1&b=2
local function encode(params)
  if params == nil then return nil end
  if type(params) == "string" then return params end
  local parts = {}
  for key, value in pairs(params) do
    parts[#parts + 1] = host.url_encode(tostring(key))
      .. "=" .. host.url_encode(tostring(value))
  end
  return table.concat(parts, "&")
end

-- host.http 返回 {status, headers, body}，状态码由插件自己解释
local function send(method, path, query, payload)
  local url = BASE .. path
  local params = encode(query)
  if params and params ~= "" then url = url .. "?" .. params end

  local body, contentType = nil, nil
  if type(payload) == "table" then
    body, contentType = host.json_encode(payload), "application/json"
  elseif type(payload) == "string" then
    body, contentType = payload, "application/x-www-form-urlencoded"
  end

  local response = host.http({
    url = url,
    method = method,
    headers = {
      ["Cookie"] = host.storage_get("cookie") or "",
      ["Content-Type"] = contentType or "application/json",
    },
    body = body,
  })
  if response.status ~= 200 then
    return { error = { code = 40, httpStatus = response.status } }
  end
  return host.json_decode(response.body)
end

function M.get(path, query) return send("GET", path, query) end
function M.post(path, payload) return send("POST", path, nil, payload) end

function M.search(query, limit, offset)
  local body = M.get("/search", { q = query, limit = limit, offset = offset })
  if body.error then return body end

  local songs = {}
  for _, item in ipairs(body.songs or {}) do
    songs[#songs + 1] = {
      id = tostring(item.id),
      title = item.name,
      artists = { { id = tostring(item.artist.id), name = item.artist.name } },
      albumId = tostring(item.album.id),
      albumName = item.album.name,
      coverUrl = item.album.picUrl,
      durationMs = item.duration,
    }
  end
  return { songs = songs }
end

function M.lyrics(id)
  local body = M.get("/lyric", { id = id })
  if body.error then return body end
  -- 返回候选数组；客户端解析 LRC 后就得到时间轴
  return { { synced = true, lrc = body.lrc } }
end

return M

打包

把 manifest.json、main.lua、api.lua 放在同一个目录里压成 ZIP。 用 PowerShell 打包时别把父目录一起装进去，按文件逐个压： 

Compress-Archive -Path .\manifest.json, .\main.lua, .\api.lua `
  -DestinationPath .\community.example.music.zip -Force
校验

安装时客户端先把包解压到临时目录，校验清单和入口，再用一个临时 VM 跑一遍入口。 全部通过才替换旧版本；中途失败就保留原版本，正在用的插件不受影响。

    06 运行时 / ENTRY CALL CONTRACT

    入口与 call 契约

    入口文件只执行一次，必须 return 一个 table，call 是其中唯一的入口函数。 此后宿主的所有调用都走它：平台操作、事件回调、计时器。 

    return {
  call = function(operation, args)
    -- operation: string
    -- args: table（普通平台操作一定带平台 ID）
    return nil
  end,
}
    位置内容
    operation操作名，字符串。大小写敏感，按文档写成驼峰或全小写。
    args 参数表。由客户端发起的调用会额外带上 args.platform（即清单里的 provider）；事件回调带各自的字段，见 事件回调。
    返回值任意可跨边界的数据，见下方类型规则。返回 nil 表示「没有内容」，不是错误。

    可以跨边界的数据

    Lua 与宿主之间只能传 nil、布尔值、数字、字符串、数组和字符串键表。 函数、协程、userdata 跨边界会直接报错 Only data can cross the plugin boundary。

    规则限制
    嵌套深度48 层
    单表键数100000
    表的键类型只能是字符串或整数；其它类型报 Invalid table key
    数组语义整数键恰好覆盖 1..n 时按数组处理，否则按字符串键表处理
    数字整数保持整数，浮点保持浮点；NaN 与无穷不可传递
    注意

    返回值里不要放函数或循环引用。序列化会失败，整次调用报错， 界面上只会说「插件请求失败」，你的错误信息到不了用户。

    分发写法

    两三个操作用 if 就够了。多起来之后可以按表分发，少一层缩进， 未实现的操作也能一起兜住： 

    local handlers = {}
handlers.describe = function(args) ... end
handlers.search   = function(args) return search(args.query) end
handlers.lyrics   = function(args) return lyrics(args.id) end

return {
  call = function(operation, args)
    local handler = handlers[operation]
    if not handler then
      error("unsupported operation: " .. tostring(operation))
    end
    return handler(args or {})
  end,
}
    提示

    未实现的操作直接 error 报出来，别静默返回 nil。 客户端解析失败只会说「插件返回了无效数据」，出错的位置只有你自己的错误信息能说明。

    07 运行时 / LIFECYCLE INSTALL → LIVE

    生命周期

    从 ZIP 到能用，中间是串行的几步。任何一步失败，已经装好的旧版本都不受影响： 客户端只在临时目录里验证通过之后才替换。

  • 解包与校验

    检查 ZIP 体积、文件类型、路径安全性、清单字段，并确认 entry 指向的文件存在。 这一步不执行任何 Lua。

  • 临时 VM 启动

    在隔离环境里加载入口、跑一遍 bootstrap。入口必须返回 table 且带 call 字段。 启动有 40 秒上限。

  • 替换与注册

    启动成功才替换旧版本。停用、更新或卸载前，客户端会先停掉该插件的请求和关联播放会话。

  • describe

    插件启用后客户端调用 describe，据此得到平台列表、名称、登录方式与能力。 旧式单平台插件可以省略它，改用清单里的 provider / capabilities / auth。

  • 注册扩展

    设置项、插件页面、播放器菜单项在入口执行时注册。注册是幂等的： 同一个插件里用相同的 id 再注册一次，更新原项，不会多出一条。

  • 会话与调用

    session 返回已登录账号或 nil。之后每次搜索、取流、取歌词都是一次 call，同一个插件的调用串行执行。

    • 状态与持久化

    会话、设置值、文件沙箱都按插件和平台分开存放。多平台插件必须用 args.platform 区分凭据，不要用一个全局 Cookie 覆盖所有账号。 选择本地音乐不会触发 logout，切换平台也不会清空其他平台的会话。

    说明

    logout 只清除当前 args.platform 的凭据。要清空整个插件的数据， 用 host.storage_clear()，或让用户在插件管理里卸载。

    08 运行时 / SANDBOX ISOLATED VM

    Lua 沙箱

    每个插件跑在独立的 VM 和独立的 isolate 里，有自己的调用队列和时间预算。 标准库里涉及文件系统、进程和动态加载的部分全部移除了。

    被移除后果
    io、os没有文件、环境变量、时钟和进程接口
    package、debug不能加载 C 模块，也不能操作调用栈
    dofile、loadfile、load、loadstring不能执行动态生成的代码
    print普通插件里为 nil；用 host.log
    require被重新实现为「从 ZIP 内加载 .lua」，见下

    require 与模块路径

    require 只能加载 ZIP 里的 Lua 文件。模块名就是文件路径去掉末尾 .lua，再把 / 换成 .：

    ZIP 内路径写法
    api.luarequire("api")
    lib/util.luarequire("lib.util")
    vendor/sign/rsa.luarequire("vendor.sign.rsa")

    同一个模块只会执行一次，结果会被缓存。加载不存在的模块报 unknown module: <name>；模块文件没有返回值时按 true 处理。 入口文件本身不能被 require，它由宿主单独加载。

    执行预算

    项目数值超限之后
    单次调用指令数250000按超时处理（code 408），VM 重建
    单次调用墙钟40 秒按超时处理（code 408），VM 重建
    启动握手40 秒插件启动失败
    host.http 单次30 秒调用失败
    host.sleep0–60000 ms按 60000 处理
    socket / websocket 接收0–30000 ms返回 nil，不报错

    后台操作有更紧的预算：scrobble、playStats、lyrics、 song 各 10 秒。这样一次卡住的上报不会堵住下一条取流请求。 stream 是用户在等的那一次调用，用默认预算，并且超时后客户端会在新 VM 上重试一次。

    注意

    指令预算比看起来容易用完。不要在 call 里对几千条数据逐条拼字符串或做嵌套排序， 批量数据交给 host.json_decode，由宿主完成。 死循环会以「插件响应超时，已自动重启插件」结束：会话还在，这次调用丢了。

    09 运行时 / ERRORS FAILURE SEMANTICS

    错误与超时

    错误分两层：Lua 抛出的错误会让当前调用失败；返回一张 { error = { ... } } 表则是「预期内的失败」，客户端会据此提示用户重试或重新登录。

    写法客户端行为
    error("boom") 调用失败，界面提示「插件请求失败」。错误文本不会直接展示给用户。
    return { error = { code = 40 } } 识别为登录态失效，提示重新登录。
    return { error = { code = 40, httpStatus = 401 } } 同上；httpStatus 优先于 code 里的状态码。
    return nil 合法的「没有内容」：未登录、无歌词、无结果。不是错误。

    把 HTTP 失败变成可读的错误

    local response = host.http({ url = url, headers = headers })
if response.status ~= 200 then
  -- 401/403 交给客户端走重新登录，429 交给重试，其余按服务端故障处理
  return { error = { code = response.status, httpStatus = response.status } }
end
    说明

    code 落在 400–599 之间时会被当作 HTTP 状态解释。业务错误码请用范围外的数值， 例如 code = 70 表示当前歌曲不可用。

    用 pcall 处理宿主错误

    host.* 在参数非法、权限没给、目标越权时都抛 Lua 错误。 可能失败的调用包在 pcall 里，沙箱的 pcall 是异步版本， 能包住会挂起的 host.http。 

    local ok, result = pcall(host.http, { url = "https://api.example.com/ping" })
if not ok then
  host.log("warn", "request failed", { reason = tostring(result) })
  return nil
end
return result

    Network permission denied目标域名不在 permissions.network 里，或不是 HTTPS

    错误码与重试

    预期内的失败返回 { error = { code, httpStatus } }，客户端据此决定提示用户重新登录、 保留重试机会，还是降一档音质再试。

    码含义客户端行为
    40未登录或登录已失效提示重新登录
    41同上（兼容旧值）提示重新登录
    44同上（兼容旧值）提示重新登录
    401HTTP 未授权提示重新登录
    429被限流保留重试机会，不弹登录
    70当前歌曲或音质不可用尝试较低音质
    408调用超时（由宿主产生）stream 会在新 VM 上重试一次
    注意

    错误对象里不要放服务端响应正文或凭据，它可能出现在界面上。需要排查细节时写 host.log，日志会被脱敏。

    36 权限 / GRANTS RUNTIME CONSENT

    授权与撤销

    授权按插件存储，用户在插件详情里可以逐项撤销。撤销不需要重启插件， 正在加载但尚未返回 Lua 的私密数据也会被丢弃。

    时机行为
    插件更新重新申请全部权限
    首次访问某域名弹出网络授权；拒绝后请求不会发出
    首次调用数据接口触发对应的数据权限申请；拒绝则抛错
    用户撤销下一次调用立即失败；进行中的请求结果被丢弃
    停用或卸载关闭该插件所有的连接与监听端口

    38 发布 / RELEASE PR FLOW

    发版流程

  • 算哈希

    打包之后算 SHA-256，把它填进清单的 sha256。

  • 自检

    在 lazer-web 仓库里跑 npm run check:plugins。它会检查字段、市场托管 ZIP 是否存在、哈希是否对得上； 加 -- --remote 还会把外部 download 抓下来对一遍。

  • 提 PR

    改 public/plugin/plugins.json，按 上架模板 写清插件类型与版本。没有自动上架通道，所有变更都要经过一次合并的 PR。

  • 合并即上线

    Vercel 会重新构建站点，/plugin/plugins.json 随即更新。 npm run build 会先跑一遍校验，清单写错时构建直接失败，坏条目不会被发布。

    41 参考 / FAQ TROUBLESHOOTING

    常见问题

    平台没出现在列表里
    describe 没返回 providers，或平台 id 不符合 ^[a-z][a-z0-9_-]{1,39}$、与别的平台重复、或者用了保留字 local。任何一条不满足都会让整个插件启动失败。
    一直报 Network permission denied
    目标主机没写进 permissions.network，或者用了 http://。 注意重定向也是不跟随的：跳到另一个域名会原样返回 3xx，那个域名同样要声明。
    首页没有推荐 / 心动模式 / 榜单
    对应能力没声明，或者声明了但返回空数组。客户端不会因为接口存在就显示一个空模块， 所以缺入口通常是 capabilities 的问题。
    歌词显示成纯文本
    没给 synced = true 和带 startMs 的 lines。 只给 lrc 字符串也能解析，但逐行数组更可靠。
    列表只有第一页
    最后一页返回了满 limit 条，客户端以为还有下一页。少返回一条，或如实按分页切片。
    请求随机超时
    单次调用有 40 秒墙钟和 25 万条指令两道预算，超时后 VM 会重建。 常见原因是循环里逐条拼字符串，或者在一个 call 里串了几十个 HTTP 请求。
    Web 版功能缺失
    浏览器不能监听端口，所以 socket 系列不存在、 websocket_server 报不支持。用 host.info().features 判断后再降级。
    更新之后权限又弹了一次
    插件更新会重置按插件存储的授权，这是有意的：避免旧授权被新代码直接复用。 把功能设计成「用户点了才申请」，这类弹窗就不会打断使用。
    装上了但什么都没发生
    先看插件管理里有没有「插件启动失败」。启动时入口必须 return 一个带 call 的 table，且 require 的模块路径要与 ZIP 内的层级一致。
